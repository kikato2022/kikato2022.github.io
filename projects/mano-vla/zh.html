MANO-VLA 把手部运动作为 Vision-Language-Action 模型的一等条件模态

一套 π0 骨架，三种推理模式 —— 纯文本、纯 MANO、 文本 + MANO —— 由 modality dropout 在训练时切换。手部运动序列被编码成 离散 MANO token 追加到多模态前缀里，动作专家自动就能看到它们，不需要任何新的融合模块。

摘要

为什么要用手部运动，以及我们拿它做什么。

Vision-Language-Action 模型的条件输入是像素和语言。而人类的操作行为，最精确的描述其实来自两只手的运动。 MANO-VLA 要问的是一个很简单的问题：一段 MANO 手部姿态序列，能不能当作机器人策略的「任务级 prompt」？

我们以 π0 为骨架（PaliGemma-3B 视觉语言专家 + 约 300M 参数的动作专家），把 离散的手部运动 token 追加到多模态前缀中。手部运动由冻结的 Being-H0 GRQ-VAE 编码 （码本 4096，k = 4 层残差），再经码本 / 部位 / 组 / 层 / 手别 / 时间六类嵌入求和投影成 2048 维前缀 token。因为 MANO token 与图像、文本处在同一个前缀块里，动作专家本来就能注意到它们： 不需要额外融合模块，也不需要扩词表。

一套权重支持三种推理模式，训练时由 {文本, MANO} 上的 modality dropout 决定：纯文本、 纯 MANO、文本 + MANO。监督信号只来自仿真（绝对关节角目标）；人类视频只提供 MANO token，不产生任何 loss。训练按阶段解冻：先做运动学自监督的 Stage A，再训动作专家加 MANO 侧，最后上 PaliGemma LoRA。

当前状态。整条链路 —— 数据 → transform → 模型 → 训练 → checkpoint → held-out 评估 —— 已经端到端跑通。但今天有的是一次 600 步的冒烟跑和一套能用的评估口径， 不是已完成的结论。下面所有数字都标了实测日期。

01三种模式，一套权重

图像和本体状态永不 dropout。modality dropout 只在文本 prompt 和整段 MANO 上独立采样， 于是恰好得到三种组合。

纯文本

常规 VLA：图像、机器人状态加一条语言指令。MANO 段整段删掉，连标签一起删。

image + state + text → action

纯 MANO

完全不给语言。只靠手部运动 token 指定任务 —— 这正是让「MANO 携带了哪些文本给不了的信息」 变得可验证的前提。

image + state + MANO → action

文本 + MANO

两种模态都在，模型自己决定怎么权衡。这是训练时的默认模式（概率 0.4）。

image + state + text + MANO → action

dropout 规格

模式图像（3 路）状态文本MANO 段初始概率
text_only有有有整段删（含标签）0.3
mano_only有有删有0.3
text+mano有有有有0.4

整段留、整段删，绝不逐 token 删：一旦出现 <mano>，N 个位置就必须填满， 某只手缺失时用 absent 占位，而不是把序列缩短。三种模式的 loss 必须分开报， 否则「能单独用」这件事无法验证。

02方法

数据侧是一个冻结的 tokenizer；模型侧只有四条接线。

前缀布局与注意力

π0 用逐 token 的 att 标记块边界，可见性按前缀和计算，因此 token 永远看不到更靠后的块。 MANO-VLA 做的事情只是「在块 A 里加 token，并把 flag 向量一起延长」，想得到的可见性关系是白拿的：

  • 块 A —— 三路图像（各 256 token）、文本 prompt（至多 256 token）与 MANO 段（约 1024 token），全部 att = 0，块内双向。
  • 块 B —— 18 维机器人状态投影成 1 个 token，att = 1：它看得到整个前缀，看不到动作。
  • 块 C —— 动作块，att = 1, 0, …, 0：动作专家看得到全部。

CPU 上有一套 23 项自检（project/scripts/smoke_pi0_mano_prefix.py），逐位核对形状、参数量、 缺手通路、梯度、掩码语义与三种模式是否与 π0 的公式一致。

MANO 这一侧

每个 token 携带码本 id、部位（腕 / 指）、组、残差层、手别，以及它覆盖的第一帧帧号。嵌入求和后只做一次投影：

# 每个 token，一层投影；不扩词表
e = proj( motion_emb[id + 4096*part] + group_emb[group] + layer_emb[layer]
          + hand_emb[hand] + time_proj( time_pe(frame0 / fps) ) )
# 缺手时把内容整体换成 absent_emb[hand]，时间 PE 保留
# <mano> 与 </mano> 是两个可学习的 2048 维向量

时间用秒编码而不是 token 序号，这样一个 token 锚定的是真实帧号，tokenizer 的 4 帧步长与位置编码解耦。 位置规则与文本一致：每 1 个 token 位置与 16 维观测交错，因此状态块从 18 维投影到模型宽度，动作维度取 16。

长前缀的代价

一个 token 覆盖 4 帧，这是对单条 (部位, 组, 层) 链说的；这样的链有 2 × 2 × k 条。取 k = 4 时，一只手每个 15 帧窗就吐 64 个 token，实测每样本中位数 1024 个（双手）。于是 MANO 模式的前向开销约为纯文本的 4 倍 （同样 600 个样本：109 s vs 466 s），要不要压缩它目前是一个待拍板项。

监督与配对

  • 一个训练样本 = 仿真里的一个时刻：state = qpos[t]（18 维），actions = action[t : t+50]（50 × 16，绝对关节角目标）。
  • MANO 与文本都从同任务、同层级里借，随机配；L*-extend 退到它对应的基础层，并打上 mano_borrowed 标记。
  • 文本标注取自仿真的描述字段。同一层级的描述是共享的 —— 这正是「纯语言交叉熵是个弱目标」的原因，见下面 Stage A。
  • 第一阶段人类段不产生任何 loss，它存在的意义只是提供 MANO token。
数据上的硬规矩。手性一律走「侧别先验」（最左框 = 左手），不用检测器的分类头 —— 这是全库体检 发现旧管线有闪烁和整只手丢失之后改的。仿真回放只走官方入口，且 L2 层级需要官方回放器没有做的 「镜像槽位还原」一步。这些规则记在 AGENTS.md 里，不每次重新讨论。

04训练

分阶段解冻，以及一套真的能否掉想法的评估口径。

阶段可训部分目标
AMANO 侧以运动学自监督为主（重建 + 时间对比），语言交叉熵只作小权重辅助项。纯文本 CE 已被否定：文本在每个 (任务, 层级) 单元上只有几 bit 的信息量，而手部运动要密得多。
B1动作专家 + MANO 侧（583.5M）flow-matching 动作损失；VLM 保持冻结。
B2再加 PaliGemma LoRA（r = 16）对视觉与语言通路做低秩适配。
B3全参微调（可选）与 Stage A 的 batch 混跑，防止 MANO 通路被动作损失冲掉。

评估口径

切分粒度是 episode，不是帧：在每个 (任务, 层级) 组内按固定步长抽段进验证集， 于是两次用同一个 val_frac 的运行必然落在同一批段上。在 H1/H2/H3 × 8 层上， 这给出 训练 1,080 段 / 412,374 样本，验证 120 段 / 45,611 样本。

评估是确定性的 —— flow-matching 的初始噪声固定种子 —— 所以不同 checkpoint 可以直接比。 报数按模式、按 (模式, 任务, 层级)、按动作维分别给出，并且永远附带一条「预测 0」的基线， 让「什么都没学到」一眼可见。证据分三级：离线码本重建曲线、held-out 动作块 MAE、最后才是仿真闭环成功率。

复现命令

# CPU 自检：对照 pi0 的掩码公式核对 MANO 前缀接线
python project/scripts/smoke_pi0_mano_prefix.py

# Stage B1 训练，held-out 固定为 10% 的 episode
python project/scripts/train_imitator_pi0.py \
  --pretrained /path/to/pi0/model.safetensors --stage b1 --steps 600 \
  --batch-size 8 --split train --val-frac 0.1 --run-name b1_h123_split

# held-out 评估：固定噪声、按模式分别报数
python project/scripts/eval_imitator_pi0.py \
  --checkpoint .cache/train/imitator_pi0/b1_h123_split/step0000600.pt \
  --stage b1 --split val --val-frac 0.1 --max-samples 600 \
  --out .cache/eval/b1_h123_split_step600.json

训练与评估必须传同一个 val_frac，否则评的就不是 held-out。批量任务在训练服务器上跑， 卡表按 GPU UUID 指定，不用字面序号。
